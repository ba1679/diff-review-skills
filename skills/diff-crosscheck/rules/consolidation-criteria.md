# Rule 1 - 所有意見由主 agent 查證，適用相同判準

- Level: `MUST`
- 每項摘要、圖表、finding 與嚴重性意見，都由主 agent 對照本次固定範圍的程式碼與需求來源查證，再套用 `criteria` 決定是否採納；版本讀取與引用依其中的證據規則，包含未提交改動的例外。
- 草稿與 reviewer 意見地位相同，票數不決定成立與否。新增 finding 也須親自確認觸發路徑並補齊 `criteria` 要求的證據、位置與修正方向；證據不足者依 Rule 4 列待確認，或依判準排除。

## Good Example

- 程式碼證據優先於票數。

```md
Codex 認為已有 guard；草稿與 subagent 認為仍有問題。
主 agent 查證：guard 只涵蓋 NetworkError，TimeoutError 仍呼叫 clearCart() → 保留 finding。
```

## Bad Example

- 多數決取代查證。

```md
草稿與 subagent 都認為成立，二比一，維持成立。
```

# Rule 2 - 依同一問題合併 findings，再全域排序

- Level: `MUST`
- 同一根因造成的同一問題合併為一條，保留完整證據與所有位置；相同位置或修正方向只作輔助，不能單獨作為合併條件。
- 標示提出者：草稿、Subagent、Codex；多方獨立提出者另標「多方佐證」。依 `criteria` 重判嚴重性與影響後，全域重新排序。

## Good Example

- 同一根因跨位置呈現，保留證據與來源。

```md
[P1] 逾時仍清空購物車（提出者：草稿、Codex；多方佐證）
位置：checkoutMachine.ts#L88-L95；CheckoutPage.tsx#L52（呼叫端）。
```

## Bad Example

- 同一位置的不同問題被誤合併。

```md
同一行同時缺少權限檢查與輸入驗證，因位置相同而合併成一條 finding。
```

# Rule 3 - 採納的修正直接回寫，排除項保留統計

- Level: `MUST`
- 查證屬實的摘要、分組、必要性與圖表問題，直接修正最終報告；證據標記與變更／影響範圍依 `criteria` 校正，不以文末勘誤保留錯誤版本。
- 不符合 `criteria` 的意見排除，依結果樣板記錄數量與類型；偏好類不必逐條列出。

## Good Example

- 本文已修正，排除紀錄仍可追溯。

```md
Summary.tsx 未修改，但讀取本次變動的資料 → 圖中改標 affected 並說明原因。
排除 3 項：不成立 1、個人偏好 2。
```

## Bad Example

- 錯誤版本仍留在本文。

```md
註：reviewer 指出上圖應為 affected 而非 changed。（圖未修改）
```

# Rule 4 - 無法判定的意見列待確認，保留仍成立的疑慮

- Level: `MUST`
- 查證後仍缺執行期、需求或外部系統證據的意見與分歧，依結果樣板列入「待確認」，交代各方主張、已查證部分與取得缺少證據的方式。
- 對象若仍符合 finding 成立條件，保留在「建議修正」並維持待驗證狀態，同時與「待確認」互相引用。

## Good Example

- 缺口具體，符合條件的疑慮仍可見。

```md
建議修正：P0 待驗證疑慮「重試可能重複扣款」→ 參見待確認。
待確認：前端未帶冪等鍵；Codex 主張後端去重，但未提供證據。
缺口與取得方式：需後端 API 文件或測試環境重現；參見該 finding。
```

## Bad Example

- 尚未判定就刪除疑慮。

```md
後端是否去重無法確認，所以刪除 finding，也不列待確認。
```

# Rule 5 - 複核狀態忠於實際執行，驗證缺口向下傳遞

- Level: `MUST`
- 複核結論依已載入的派發規則判定，與報告開頭的「報告狀態」一致；結果樣板的 reviewer 狀態填「完成、未完成、未執行」，未完成時附原因。
- 檢查與限制依 reviewer 實際回報填寫，Codex 模型與重試經過取自狀態 JSON 的 `attempts`；任一方未驗證的面向，最終報告不得寫成已驗證。
- 依結果樣板填寫統整統計、工作目錄檢查與原始結果路徑；原始複核全文不併入本文。

## Good Example

- 完成複核仍保留驗證限制。

```md
兩方均完成；Codex 的 attempts 記錄模型 A 容量不足，改用預設備援 B 接續完成。
兩方都未執行測試 → 最終報告記錄未執行測試。
```

## Bad Example

- 未驗證被寫成通過。

```md
Reviewer 無法讀取 Jira 需求，最終報告卻寫「需求符合度已驗證」。
```
